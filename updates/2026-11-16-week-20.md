# EPF Week 20 - Ivan Anishchuk - leanp2p at Machine-Checked Devcon Week

## leanp2p

A consensus client finds peers and moves blocks and attestations over libp2p. The consensus spec
fixes the stack. Transports: QUIC first, TCP as the fallback. Security: Noise or TLS. Then yamux,
multistream-select, identify, req/resp and gossipsub. leanp2p builds that stack in Lean, so the
pure parts can carry proofs.

The code is split into 22 small packages, each with its own architecture doc and plan. The work
was a task tree of units that contributors claimed one at a time. Imports only point down, and a
lint checks that on every change.

### What I built

I worked bottom up, one unit per pull request, and my units ended up in 15 of the 22 packages:

- The base: concurrency primitives (channels, select, task sets, a clock seam), the varint
  codec, and the connection layer with an in-memory transport for tests.
- Transports and crypto: TCP over libuv, an OpenSSL 3 backend behind a crypto facade, and yamux.
- Identity: keys, peer ids, and EIP-778 node records over an RLP codec of its own.
- The middle of the stack: the core interfaces every package plugs into, Noise XX, the host
  (dial, listen, deduplication, shutdown) and req/resp in `ssz_snappy`.
- The interop harness that runs the stack against go-libp2p in Docker.

Each package started on mocks of its neighbors. Once the real packages existed, I moved the
security, host, negotiation and protocol packages off their mocks, then ran the host, identify,
ping, req/resp and the CLI on the real stack end to end.

Two units go past the original plan. The libp2p TLS handshake runs over libssl and checks the
peer's certificate inside the handshake. The spec makes QUIC the primary transport, so I added it
at the end of the week, over ngtcp2 and the same TLS code.

Other contributors built the byte model, multiformats, protobuf, snappy, the pure digests,
multistream-select, identify and ping, the muxer values and mplex, gossipsub v1.1 and the demo
CLI.

### How it's checked

- Theorems cover the pure codecs and state machines; the codecs are stated over a simple byte
  model. The repo has 774 theorems and no `sorry`. Decoders read back what encoders wrote, the
  yamux window stays in bounds, and both peers of a simultaneous dial keep the same connection.
- The decoders that run in production are checked against the proved model by property tests.
- C code (OpenSSL, libssl, ngtcp2) is checked against captured vectors and live peers. Each PR
  lists what it trusts, and none adds an axiom.
- Live interop with go-libp2p: 13 matrix entries over TCP with Noise or TLS and over QUIC, with
  Lean and Go each as dialer and listener. Separate TLS and QUIC runs check that a bad
  certificate gets the right alert.
- 28,331 checks in the suite.

### What the checks found

- Stress-testing turned up an occasional test hang: a test clock moved before a timer was armed.
  Repeated reruns after the fix came back clean.
- Running two real hosts showed the Noise reader handing over one byte at a time, so a 70 KB
  answer took 3 to 9 seconds. Reading whole frames brought it to about 50 ms.
- etheorem's SHA-256 library crashed every program that linked it. I sent the fix upstream
  ([#153](https://github.com/etheorem/etheorem/pull/153)), and it's in review.
- OpenSSL signs with out-of-range secp256k1 keys, so the shim checks the range itself.
- Stress-testing QUIC found three more problems:
  - A canceled UDP receive in Lean v4.34 leaks its socket. The loop wakes its reader with a
    datagram to itself until v4.36 fixes the cancel.
  - Lean's UDP bind lets two sockets share a port, which occasionally hung a run. The shim now
    binds each socket without reuse, and extensive reruns came back clean.
  - QUIC lets a server close before the client's last handshake message arrives, so the tests
    allow it.

Since the close I've opened three more fixes
([#103](https://github.com/etheorem/leanp2p/pull/103),
[#104](https://github.com/etheorem/leanp2p/pull/104),
[#105](https://github.com/etheorem/leanp2p/pull/105)). The leaks LeakSanitizer reports predate
QUIC and are tracked in [#102](https://github.com/etheorem/leanp2p/issues/102).

## Next

- Get QUIC ([#101](https://github.com/etheorem/leanp2p/pull/101)) reviewed and merged, and fix
  the open issues.
- The consensus networking: discv5, the consensus fields of node records, the rest of gossipsub,
  and the eth2 req/resp service (Status, Ping, MetaData, Goodbye), checked against rust-libp2p as
  well as go-libp2p.
- A Lean consensus node running on leanp2p, first on a devnet, then on a public testnet.
- The core etheorem work continues: improving the model, adding proofs, and optimizing the parts
  of the model a client runs on every block.
- The longer goal: an experimental client with etheorem for the consensus logic and leanp2p for
  the networking.
