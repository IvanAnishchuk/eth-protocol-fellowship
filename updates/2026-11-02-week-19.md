# EPF Week 19 - Ivan Anishchuk - toward a client: a shadow node and libp2p in Lean

Short version:

- Started on running the etheorem model as a client, the first item on my future-work list.
- A shadow node follows a devnet through the etheorem Fulu model and checks every block against
  Lighthouse, with its own Geth, its own Beacon API, and a p2p node in Lean.
- [leanp2p](https://github.com/etheorem/leanp2p), libp2p in Lean 4: four work units merged
  (concurrency, varint, connections, the OpenSSL backend), two more open.
- [#120](https://github.com/etheorem/etheorem/pull/120) merged, and the Lighthouse team has
  started verifying their code against etheorem.
- Prepared the EPF Day talk at Devcon with Raj Gill.

## Shadow node

The shadow node replays a beacon node's blocks through the etheorem Fulu model and reports,
block by block, whether the model reaches the same state and head as the client. Every block
goes through the model with real BLS and KZG checks, and `state_transition` asserts the block's
`state_root`, so "agree" means the same state.

- It keeps one fork-choice store, from genesis or from a checkpoint, and feeds it the blocks,
  data columns and the host's gossip votes. It compares the head and both checkpoints with the
  host (Lighthouse).
- It drives its own Geth over the Engine API (`engine_newPayloadV4`, then
  `engine_forkchoiceUpdatedV3` with the model's head), so the execution side follows the model's
  fork choice. An `INVALID` payload counts as a disagreement. The JWT and HMAC-SHA256 are in Lean.
- It serves a read-only Beacon API (`v4.0.0`) from its own store, and a Lighthouse node can
  checkpoint-sync from it. `api-diff` compares every endpoint with the host's.
- `shadow_node` joins the p2p network as one Lean process. A Rust library over Lighthouse's
  network crate only moves bytes across a four-function C ABI. The event loop, sync, column
  assembly and gossip validation are in Lean. It's the stand-in until leanp2p can do the job.
- It runs on Kurtosis devnets: one node, and three nodes (two Lighthouse, one Grandine, 1056
  validators) with BLS changes, slashings, exits and top-up deposits in the blocks.

What a real network showed:

- The pyspec store never prunes. The node prunes to the finalized checkpoint after every step,
  which differs from the spec in two cases: a block on a pruned parent fails on the missing key
  (the spec rejects it on the finalized check), and a vote for a pruned block fails where the
  spec accepts it with no weight.
- At an epoch boundary every column message ran the proposer check, and each check ran an epoch
  transition: one slot kept the loop busy for 100 s. Taking the proposer from a table computed
  once per parent and slot brought it to 7 s.
- Columns weren't arriving over gossip, because the partial-column topics send only the cells a
  node asks for. After requesting every cell, columns complete 0.2–0.5 s after the block, block
  lag fell from 12 s to 2–6 s, and 1723 of 2011 attestations validated.
- A few Beacon API differences: Lighthouse always answers `finalized: false` for
  `state_id=justified`, even before the first justification, when that state is the finalized
  one, and `v4.0.0` has no Fulu `BeaconState` schema.

It's not a client yet. It serves no blocks or columns to peers and doesn't rebuild columns from
half of them.

## leanp2p

[leanp2p](https://github.com/etheorem/leanp2p) is a libp2p stack in Lean 4, aimed at the
consensus layer first (tcp + noise + yamux, identify, req/resp, gossipsub v1.1), built
package by package with several contributors and Leo's spike branch as the reference.

Merged:

- W1.1, `base/conc` ([#27](https://github.com/etheorem/leanp2p/pull/27)): bounded `Chan`,
  `select`, `Pipe`, `TaskSet`, `OnceRef`, `withinDeadline` and a `Clock` seam. Everything that
  can block runs in `Async`. [#38](https://github.com/etheorem/leanp2p/pull/38) renames its
  theorems to lowerCamelCase.
- W2.1, `codec/varint` ([#34](https://github.com/etheorem/leanp2p/pull/34)): the unsigned varint
  with its `LawfulCodec` laws. A non-minimal form and a ninth continuation byte are `malformed`,
  a cut-off input is `truncated`.
- W4.1, `net/streams` ([#32](https://github.com/etheorem/leanp2p/pull/32)): `Connection`,
  `Listener` and the `Transport` seam with a simulated transport, `BufReader`, `Framing` with its
  size caps, and a 30 s deadline before a connection is authenticated.
- W3.2, `crypto/backend` ([#39](https://github.com/etheorem/leanp2p/pull/39)): the OpenSSL 3
  shim, its Lean bindings with a regression per verifier rule, and pins to etheorem's hazmat
  packages. Three of four pins landed; SHA-256 stayed on the backend because of a crash in
  `LeanHazmatSha256` (below).

Open:

- W3.3, the `Crypto` facade, the `Rng` seam, and a cross-check between the pure copies and the
  production path ([#41](https://github.com/etheorem/leanp2p/pull/41)).
- W6.1, the EIP-778 ENR codec: decode and verify, sign, the `enr:` text form and the map to a
  peer id and multiaddrs, over the package's own RLP with its `LawfulCodec` proved
  ([#43](https://github.com/etheorem/leanp2p/pull/43)). It stacks on #41.

## etheorem

- [#120](https://github.com/etheorem/etheorem/pull/120) merged: an append to a full SSZ list now
  raises, as remerkleable does.
- [#153](https://github.com/etheorem/etheorem/pull/153), the `LeanHazmatSha256` crash from the
  leanp2p pins: a `__libc_csu_init` stub in the SHA-256 shim replaced glibc's, so no static
  constructor ran, and every executable linking it segfaulted on its first uncaught-error print.
  The PR drops the stubs and the system `-L` that made them necessary.
- The Lighthouse team has started verifying Lighthouse against etheorem. Eitan Seri-Levi's
  [post](https://unclebill.blog/posts/etheorem-and-a-small-spec-inconsistency) describes an
  equivalence proof of their Gloas epoch processing, and his fixes making the model raise where
  the spec does ([#146](https://github.com/etheorem/etheorem/pull/146),
  [#151](https://github.com/etheorem/etheorem/pull/151)) let them drop two preconditions: on any
  state, Lighthouse and etheorem now reach equal states or both fail.
